## Codex-LHC v0.3.1

Fixes a code-mode compact continuation failure that stranded agents near
the context ceiling. The first sustained real code-mode session under
v0.3.0 demonstrated gaps in the LIM-67 protected compact-continuation
state machine and the compact-point selection algorithm.

### Changes

**Exact provider-native protected-pair preservation.**
Forward mapping discards `CustomToolCall.status` and flattens structured
`ContentItems` output into joined text. The byte-stable validator correctly
rejected the reconstructed pair. v0.3.1 grafts the exact live
`ResponseItem` objects into the complete serialized response-item history
before validation, rollout rewrite, and in-memory install. Provider-visible
fields are preserved verbatim.

**Compact-point selection: remove empty-tail raw-retention override.**
The compact-point selector unconditionally retained oversized turns in the
full tier when no PI-mappable message existed after the crossing turn. A
577K-token single turn stayed at full fidelity in the tail even though its
smooth representation was 43K tokens. v0.3.1 removes the empty-tail
override and adds `compact_continuation_marker` to the mappable-kind set.
During protected escalation, the compact point is constrained to the
greatest legal closed-turn boundary at or before the protected visibility
boundary, so protected pairs remain in the exact tail.

**Blocked task-loop containment.**
When mid-turn compact-continuation determined the next provider request was
not allowed, the error was converted to a non-specific failure that the
pending-input loop treated as loop-eligible. Pending subagent messages
triggered another compact and provider request. v0.3.1 propagates a typed
task-loop stop that terminates the current RegularTask. Pending input is
preserved for later recovery.

**Complete serialized response-item sizing.**
The host body-size estimator assigned a constant 64 characters to every
non-message item. A 38,811-character tool result estimated at approximately
16 tokens instead of approximately 10,000. v0.3.1 replaces the estimator
with complete JSON serialization plus o200k token counting. Body-size
checks are diagnostic, not terminal — an oversized body proceeds with
observability rather than stranding the thread.

**Stale host-validation supersession.**
After a failed host validation, the reload gate blocked rollout
regeneration indefinitely. v0.3.1 scopes the reload block to the installed
view. A newer successfully installed active view supersedes the old failure.

**Terminal trigger-gate demotion.**
The auto-compact trigger was used as a terminal compact-success gate. A
body above the trigger but within the provider window was refused, stranding
the thread. v0.3.1 demotes body-size gates from terminal refusal to
diagnostic logging. The pending-tool safe-runway threshold uses the provider
context window, not the auto-compact trigger.

### Compatibility

- LHC thread schema remains v11. No additional migration is required for
  v0.3.0 threads.
- Opening a schema-v6 thread (from v0.2.1) with v0.3.1 migrates it to
  schema 11; downgrade to v0.2.1 after migration is unsupported.
- Native compact fallback remains disabled.
- LHC capture enabled by default.

### Known limitations

- The compact-continuation selected-candidate stage log may report the
  initial candidate after a maximal-prune retry selected a different
  candidate. This is an observability issue tracked separately.

### Validation

  two-block `ContentItems` output passes graft and byte-stable validation.
- Grafted protected pair survives rollout rewrite, `patch_materialized_history_ids`,
  and `history_from_materialized_items` resume round-trip.
- Blocked host validation with pending mailbox input returns `TurnAborted`
  and preserves queued input.
- View-scoped reload gate blocks the failed view and clears after a later
  standalone compact installs a different view.

  tests prove provider-native shape preservation.
