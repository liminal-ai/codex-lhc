# Codex + LHC v0.153.4

This release packages Codex-LHC 0.153.4, based on upstream Codex annotated
tag `rust-v0.153.4` (tag object `042fb41b7c813ac7999105e886b2b7aa715b5081`,
peeled commit `3d2ee51ca2d5db578f328aa75e20aa22c0197c9a`), with the exact
certified LHC SDK pin `e9456a6ee23a10cf04e15b16bcf77738c52b0f7c` (thread
schema 13: content blocks and blob storage on top of the schema-12 turn parts).

Changes over v0.150.2:

- Upstream moves from 0.150.1 to 0.153.4 (0.153.3 sync plus the 0.153.4
  hotfixes: Astra listed in the bundled model picker, async-question guidance
  qualified by tool availability).
- The fork reports its own release identity: `codex-lhc --lhc-version` prints
  the fork release (`0.153.4`, or `0.153.4-lhc.N` for a fork revision) while
  `--version` keeps reporting the upstream base.
- The installers name a new install `codex-lhc` by default, leave any stock
  `codex` command alone, record the command name and prefix in the package
  store, and on Linux/macOS refuse an occupied unmanaged command name before
  the store changes.
- `codex-lhc update` and the TUI update prompt re-run the fork installer
  against the managed package store; installs the fork installer did not make
  get manual instructions instead. Update discovery, its cache
  (`lhc-version.json` in `CODEX_HOME`), and `codex-lhc doctor` compare fork
  releases from the fork's release feed rather than upstream's.
- Schema-13 image content blocks are integrated end to end and served image
  attributes are preserved through compaction.
- LHC derivations are routed through the SDK inference adapter with the
  proper templates; before this fix (incident 2026-09-05) the bridge sent bare
  input, so model-derived rows were replies rather than derivations.
- Upstream's experimental context management / token-budget modes are
  rejected at thread startup while LHC capture is active, instead of silently
  competing with LHC compaction.
- Code Mode uses verified upstream V8 artifacts with the sandbox feature
  enabled.

## Thread schema and migration

LHC thread schema advances from 12 to 13. Opening a schema-12 (or older)
thread with v0.153.4 migrates it in place, in one transaction, to schema 13;
nothing is copied. v0.150.2 and earlier cannot open a migrated thread, and
there is no downgrade.

## Packages

The five native archives (Linux x86-64/ARM64, Windows x86-64/ARM64, Apple
Silicon macOS) retain the canonical Codex package layout. Every package
contains Codex, Code Mode host, bundled ripgrep, canonical metadata, and LHC
provenance. Linux packages also contain bwrap and patched zsh; Windows
packages contain the command runner and sandbox setup helpers.

## Qualification

- Source integration: the full local tripwire (capture, certification,
  compact arm, full loops, recovery-patch drill at the new base) is green on
  the accepted source on Linux x86-64.
- Candidate builds, native readiness checks, and the two independent Linux
  burn-ins will be documented in the promotion approval record. Native
  installation of the packaged Mac/Windows archives is a separate coverage
  question for release approval.
- The published-channel install-then-update check follows publication and
  will be reported separately.
- Provider-pressure compact crossing remains **not established**; this
  release makes no claim that one passed.
