# Codex + LHC v0.157.0

This release packages Codex-LHC 0.157.0 on upstream Codex 0.157.0
(`rust-v0.157.0`, peeled commit `00c972ed5d`). LHC thread schema remains 13;
opening an existing LHC thread does not migrate it. Codex's own thread-history
database does migrate (see Upgrade impact).

## What changed for users

- **Upstream 0.157.0.** This cut includes the upstream 0.157.0 Codex changes
  (128 commits) on top of the previous LHC release: GPT-6 Sol and Luna in the
  model catalog, a network policy for sandboxed commands and MCP servers, MCP
  attribution across requests, a fullscreen transcript by default, and the
  0.157.0 TUI and app-server additions.
- **Background server stays off.** Upstream 0.157.0 starts a shared background
  app-server by default. This fork keeps it off; Codex runs in-process as
  before. Set `features.daemon_auto_start = true` to opt in.
- **Guardian keeps its thread context.** Upstream's thread-owned Guardian
  context is on by default here as well. The fork's carry of Guardian history
  across an LHC compaction and a reopen was re-ported onto upstream's new
  history reconstruction.
- **Cold reopen after an LHC compaction.** The LHC fold now records the same
  resume metadata upstream writes for its own compactions, so 0.157.0's
  reopen-from-the-latest-compaction path selects the LHC fold rather than
  replaying the whole rollout.

## Known limitations

- Threads rewound under 0.155.1 or earlier can surface rewound turns via
  retrieval and after compaction. Native rewind never removed those turns from
  the LHC record, and this release does not rewrite them away.
- Editing a previous prompt (Esc, Esc) after a compaction says the prompt was
  not found. Rewinding stays unsupported on LHC threads either way.
- Quitting Codex or pressing Ctrl-C while a background summary is starting can
  leave that summary failed. That stretch of the conversation then shows as an
  excerpt instead of a summary.
- Background work that finishes after a compaction logs "unknown turn"
  warnings. The results still arrive.
- The background app-server (daemon) mode is not qualified with LHC in this
  release; it is off by default and stays a proposal.

## Upgrade impact

- **Thread-history database migrates one way.** Upstream 0.157.0 adds thread
  item lifecycle timestamps as migration 0007, so the fork's rollout-generation
  migration moves to 0008. On first open, the fork relabels its own earlier
  migration row (version 5 on homes first migrated before 0.155.1, version 7
  on 0.155.1 and 0.156.1 homes) to 0008 and then applies upstream's 0007.
  This happens once and needs no action.
- **Rollback to 0.156.1** requires restoring a backup of
  `thread_history_1.sqlite` (with its `-wal`/`-shm` files) taken before the
  first 0.157.0 open; 0.156.1 refuses the migrated database. LHC thread stores
  need nothing: the LHC core pin (`47e360a3`) is unchanged. Rollouts written
  by 0.157.0 carry an extra `resume_metadata` field that 0.156.1 ignores.
- LHC thread schema remains 13. Releases v0.150.2 and earlier cannot reopen
  migrated threads. See [upgrade details](lhc-docs/INSTALL.md#upgrade-and-compatibility).

## Packages

The five native archives (Linux x86-64/ARM64, Windows x86-64/ARM64, Apple
Silicon macOS) keep the canonical Codex package layout. Every package contains
Codex, Code Mode host, bundled ripgrep, canonical metadata, and LHC
provenance. Linux packages also contain bwrap and patched zsh; Windows
packages contain the command runner and sandbox setup helpers.
