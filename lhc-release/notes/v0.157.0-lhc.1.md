# Codex + LHC v0.157.0-lhc.1

Codex-LHC 0.157.0-lhc.1 is a fix release on the same upstream Codex 0.157.0
(`rust-v0.157.0`, peeled commit `00c972ed5d`) and the same LHC core (pin
`47e360a3`) as v0.157.0. `codex --version` still reports `codex-cli 0.157.0`;
`codex --lhc-version` reports `0.157.0-lhc.1`. Nothing stored changes shape:
LHC thread records and Codex's thread-history database are exactly as v0.157.0
leaves them, and going back to v0.157.0 is a version switch.

## What changed for users

- **Compaction no longer stops on a reply with no text.** When the model's
  final message was empty (Codex records it as an assistant message with empty
  text), every later compaction of that thread failed with `LHC compact failed:
  … mapper produced zero events`, and the turn failed with it; a seat on the
  t3code console lost its thread that way on 2026-09-25. Such an item holds
  nothing the LHC archive could keep, so the import now logs a warning and skips
  it, and the compaction continues on what the archive has. History items of a
  type the archive cannot represent were refused the same way and are now
  skipped the same way. Both stops date from 2026-08-15 and were missed by the
  compact-gating triage; this follows its rulings of 2026-08-19 (detect, warn,
  continue with the best available body).

## Known limitations

Carried from v0.157.0, unchanged:

- Threads rewound under 0.155.1 or earlier can surface rewound turns via
  retrieval and after compaction. Native rewind never removed those turns from
  the LHC record, and this release does not rewrite them away.
- Esc, Esc opens upstream's transcript browser. Choosing a prompt there to
  rewind an LHC thread is refused with `Rewinding is not yet supported.` and
  the prompt is left in the composer to edit and resend.
- Quitting Codex or pressing Ctrl-C while a background summary is starting can
  leave that summary failed. That stretch of the conversation then shows as an
  excerpt instead of a summary.
- Background work that finishes after a compaction logs "unknown turn"
  warnings. The results still arrive.

Other conditions in the compaction path still fail the compaction instead of
continuing. They are unchanged in this release and listed for review in the
release's campaign record.

## Rolling back to 0.157.0

1. Close Codex.
2. Reinstall v0.157.0 (`install.sh --version 0.157.0`, or point `current` back
   at the retained 0.157.0).

There is nothing to restore. Rolling back further, to 0.156.1, is as described
in the v0.157.0 notes: it needs the `thread_history_1.sqlite` backup taken
before the first 0.157.0 open.

## Qualification

- **The failure, reproduced on installed v0.157.0** through the app-server path
  (what the t3code seats run): a thread with one turn; one empty-text assistant
  message appended to its rollout (the exact shape of the seat's record:
  `role: assistant`, `content: [{output_text, ""}]`, `phase: final_answer`);
  `thread/resume`; `thread/compact/start`. The compaction turn failed with
  `unsupported operation: LHC compact failed: lhc open failed: cannot safely
  import host Message into archive (mapper produced zero events)`.
- **The same sequence on the fixed build** (local Linux release build of the
  fix): the compaction turn completed, one compacted item landed in the
  rollout, the log carried one `LHC import: host item maps to zero events;
  skipped, compact continues without it` line for the message, and the facts
  planted before the compaction were recalled after it; every derivation ready. The exact Linux candidate artifact goes through the
  same sequence before promotion; that result is in the approval record.
- **Unit tests** (`codex-lhc-host`, `compact_bridge.rs`): an empty assistant
  message compacts and leaves the archive unchanged; the import skips
  zero-event and unrepresentable items and counts only what it wrote; an
  unrepresentable item in host history no longer refuses compact. All three
  fail with the fix reverted. Host crate 241/241; core `compact_lhc` 133/133;
  clippy adds no warning (one pre-existing too-many-arguments note on an
  untouched function). `cargo check --workspace` fails on this machine at
  `glib-sys` (system library absent); the tripwire's check layer, scoped to the
  hooked crates, is the gate. The Guardian, network-approval and code-mode
  integration suites fail 68 tests on this machine, the same 68 on the
  unmodified v0.157.0 tree (no sandbox user namespaces, no screenshot tooling);
  the fix adds none. The fork's tripwire script passes every layer on the cut
  tree.
- **Live cases** of the release catalog on the same local build: cases 1-7 and
  10 through the TUI (open and trust, subagent then `/compact` then a prompt,
  rewind refused, Guardian review, second compaction with recall of the planted
  facts, SIGKILL then reopen then a prompt, `exec resume`; 54 derivations
  ready, no user message with a foreign provider id, no provider rejection) and
  case 8 through the app-server (two turns, `thread/compact/start`, recall,
  `thread/revert` refused, reopen in a new process, recall). Sandbox and
  network-policy paths not run (no user namespaces on the build machine). The
  same cases on the exact artifact are recorded in the approval record.
- **Platforms:** built on all five; exercised on Linux x86-64 only.

## Packages

The five native archives (Linux x86-64/ARM64, Windows x86-64/ARM64, Apple
Silicon macOS) keep the canonical Codex package layout. Every package contains
Codex, Code Mode host, bundled ripgrep, canonical metadata, and LHC
provenance. Linux packages also contain bwrap and patched zsh; Windows
packages contain the command runner and sandbox setup helpers.
