# Codex + LHC v0.157.1

Codex-LHC 0.157.1 is upstream Codex 0.157.1 (`rust-v0.157.1`, peeled commit
`36650394c5`) with the LHC integration carried forward, plus one LHC fix. The
LHC core is unchanged from 0.157.0 (pin `47e360a3`), LHC thread records are not
migrated, and Codex's thread-history database is exactly as v0.157.0 leaves it
(0.157.1 adds no migration). Going back to v0.157.0 is a version switch.

## What changed for users

- **Upstream 0.157.1, Windows only.** Four fixes, all inside Windows-only code:
  the Code Mode host and local stdio MCP servers are launched without a console
  window; the background app-server launch no longer refuses a process that
  still belongs to an outer Job Object; and a detached background app-server no
  longer inherits the launcher's output pipes, which left callers waiting for
  EOF. The background app-server stays off by default in this fork
  (`features.daemon_auto_start`), so the last two apply only when it is turned
  on. Linux and macOS binaries behave as in v0.157.0.
- **Compaction no longer stops on a reply with no text.** When the model's
  final message was empty (Codex records it as an assistant message with empty
  text), every later compaction of that thread failed with `LHC compact failed:
  … mapper produced zero events`, and the turn failed with it; a seat on the
  t3code console lost its thread that way on 2026-09-25. Such an item holds
  nothing the LHC archive could keep, so the import now logs a warning and skips
  it, and the compaction continues on what the archive has. History items of a
  type the archive cannot represent were refused the same way and are now
  skipped the same way. Both stops date from 2026-08-15 and were missed by the
  compact-gating triage; this follows its rulings of 2026-08-19 (detect, warn,
  continue with the best available body).

A `0.157.0-lhc.1` candidate carrying only the second change was built and
qualified on 2026-09-26 but never published; this release supersedes it.

## Known limitations

Carried from v0.157.0, unchanged:

- Threads rewound under 0.155.1 or earlier can surface rewound turns via
  retrieval and after compaction. Native rewind never removed those turns from
  the LHC record, and this release does not rewrite them away.
- Esc, Esc opens upstream's transcript browser. Choosing a prompt there to
  rewind an LHC thread is refused with `Rewinding is not yet supported.` and
  the prompt is left in the composer to edit and resend.
- Quitting Codex or pressing Ctrl-C while a background summary is starting can
  leave that summary failed. That stretch of the conversation then shows as an
  excerpt instead of a summary.
- Background work that finishes after a compaction logs "unknown turn"
  warnings. The results still arrive.

Other conditions in the compaction path still fail the compaction instead of
continuing. They are unchanged in this release and listed for review in the
release's campaign record.

## Rolling back to 0.157.0

1. Close Codex.
2. Reinstall v0.157.0 (`install.sh --version 0.157.0`, or point `current` back
   at the retained 0.157.0).

There is nothing to restore. Rolling back further, to 0.156.1, is as described
in the v0.157.0 notes: it needs the `thread_history_1.sqlite` backup taken
before the first 0.157.0 open.

## Packages

The five native archives (Linux x86-64/ARM64, Windows x86-64/ARM64, Apple
Silicon macOS) keep the canonical Codex package layout. Every package contains
Codex, Code Mode host, bundled ripgrep, canonical metadata, and LHC
provenance. Linux packages also contain bwrap and patched zsh; Windows
packages contain the command runner and sandbox setup helpers.
