# Codex + LHC v0.157.1

Codex-LHC 0.157.1 is upstream Codex 0.157.1 (`rust-v0.157.1`, peeled commit
`36650394c5`) with the LHC integration carried forward from v0.157.0, plus one
LHC fix: compaction no longer stops on a model reply with no text. The LHC core
is unchanged (pin `47e360a3`). `codex --version` reports `codex-cli 0.157.1`;
`codex --lhc-version` reports `0.157.1`.

Nothing stored changes shape: LHC thread records and Codex's thread-history
database are exactly as v0.157.0 leaves them, so upgrading from v0.157.0 needs
no backup and going back to v0.157.0 is a version switch. Upgrading from 0.156.1
or earlier still runs v0.157.0's one-way thread-history migration: follow
"Before you upgrade" in the [v0.157.0 notes](v0.157.0.md) first.

## Should you upgrade

- **Yes, if a thread fails every compaction with `LHC compact failed: …
  mapper produced zero events`** (or `unrepresentable host item`). That thread
  cannot compact on v0.157.0; on v0.157.1 it compacts again.
- **On Windows**, upstream's changes stop console windows flashing up for local
  MCP servers and the Code Mode host. These were built but not run on Windows
  for this release.
- Otherwise the release is small: one fix in the LHC compaction import and
  upstream's Windows-only changes. Linux and macOS behaviour is otherwise that
  of v0.157.0.

## What changed

- **Compaction no longer stops on a reply with no text.** When the model's
  final message was empty (Codex records it as an assistant message with empty
  text), every later compaction of that thread failed with `LHC compact failed:
  … mapper produced zero events`, and the turn failed with it; a seat lost its
  thread that way on 2026-09-25. Such an item holds nothing the LHC archive
  could keep, so the import now logs a warning (`LHC import: host item maps to
  zero events; skipped, compact continues without it`) and skips it, and the
  compaction continues on what the archive has. History items of a type the
  archive cannot represent were refused the same way and are now skipped the
  same way, with their own warning. This follows the compact-gating rulings of
  2026-08-19 (detect, warn, continue with the best available body); the two
  stops dated from 2026-08-15 and had been missed by that triage.
- **From upstream 0.157.1, Windows only:** console windows are suppressed when
  Codex starts local MCP servers and the Code Mode host, and the background
  app-server launches without holding the launcher's console and tolerates an
  existing job membership. Codex-LHC keeps the background app-server off by
  default (`features.daemon_auto_start`), so the launch changes matter only if
  you opted in. See the
  [upstream release](https://github.com/openai/codex/releases/tag/rust-v0.157.1).

Integrating upstream 0.157.1 took no LHC changes: its only overlap with the
fork is the workspace version line in `codex-rs/Cargo.toml`, the one merge
conflict.

## What to weigh

- **The skip is by design silent to the conversation.** A skipped item is
  logged, not shown. Items skipped this way carry no text or content the
  archive could hold, so nothing the model said is lost; but if a future mapper
  bug made a real item map to nothing, it would now be skipped with a warning
  instead of stopping the compaction. Look for the `LHC import:` warnings in
  the log if a compacted thread seems to be missing something.
- **Other compaction stops remain.** Conditions in the compaction path other
  than these two still fail the compaction instead of continuing; they are
  unchanged in this release.
- **Windows changes are untested here.** Windows packages were built; no
  Windows run was made for this release.

## Known limitations (unchanged from v0.157.0)

- Threads rewound under 0.155.1 or earlier can surface rewound turns via
  retrieval and after compaction. Native rewind never removed those turns from
  the LHC record, and this release does not rewrite them away.
- Esc, Esc opens upstream's transcript browser. Choosing a prompt there to
  rewind an LHC thread is refused with `Rewinding is not yet supported.` and
  the prompt is left in the composer to edit and resend.
- Quitting Codex or pressing Ctrl-C while a background summary is starting can
  leave that summary failed. That stretch of the conversation then shows as an
  excerpt instead of a summary.
- Background work that finishes after a compaction logs "unknown turn"
  warnings. The results still arrive.

## Rolling back to 0.157.0

1. Close Codex.
2. Reinstall v0.157.0 (`install.sh --version 0.157.0`, or point `current` back
   at the retained 0.157.0).

There is nothing to restore. A thread that hit the empty-reply stop fails its
compactions again on v0.157.0. Rolling back further, to 0.156.1, is as
described in the v0.157.0 notes: it needs the `thread_history_1.sqlite` backup
taken before the first 0.157.0 open.

## Qualification

On the code of this release (a local Linux x86-64 release build, before the
release candidate):

- **The fix, live:** a thread with one turn; an empty-text assistant message
  appended to its rollout (the shape of the failing seat's record: `role:
  assistant`, `content: [{output_text, ""}]`, `phase: final_answer`); resume;
  compact. The compaction completed, the log carried one zero-events skip line
  and no failure, and facts planted before the compaction were recalled after
  it.
- **Live catalog cases** 1-7 and 10 through the TUI (open and trust, subagent,
  `/compact`, rewind refused, Guardian review, second compaction with recall,
  kill then reopen, `exec resume`) and case 8 through the app-server: all
  passed.
- **Unit tests:** three new tests in `codex-lhc-host` (an empty assistant
  message compacts and leaves the archive unchanged; the import skips
  zero-event and unrepresentable items and counts only what it wrote; an
  unrepresentable item no longer refuses compact). Host crate 241/241. The
  fork's check script passes every layer.
- **Known machine failures:** the Guardian, network-approval and code-mode
  integration suites need sandbox user namespaces, absent on the build
  machine; their failures there are a subset of those on the unmodified
  v0.157.0 tree. Two managed-install tests fail identically on v0.157.0, and
  two OAuth token-refresh tests are flaky on that machine on both trees.
- **Not run:** sandbox and network-policy paths (no user namespaces), Windows,
  macOS and ARM64 packages (built, not exercised).

The exact Linux x86-64 release package goes through the same live cases before
publication; that result is in the release record.

## Packages

The five native archives (Linux x86-64/ARM64, Windows x86-64/ARM64, Apple
Silicon macOS) keep the canonical Codex package layout. Every package contains
Codex, Code Mode host, bundled ripgrep, canonical metadata, and LHC
provenance. Linux packages also contain bwrap and patched zsh; Windows
packages contain the command runner and sandbox setup helpers.
