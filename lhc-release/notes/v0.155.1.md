# Codex + LHC v0.155.1

This release packages Codex-LHC 0.155.1, based on upstream Codex annotated
tag `rust-v0.155.1` (tag object `4e21628f9ec9ee656650cd2b62ef92225725b5ac`,
peeled commit `be2951ea34f0d295ed0becf97079f92fa5f6950e`), with the exact
certified LHC SDK pin `e9456a6ee23a10cf04e15b16bcf77738c52b0f7c` (thread
schema 13). Source tip `dc30d2bfd969e587b0c74a422a6a5c9379cbf903`.

Changes over v0.153.4:

- Upstream moves from 0.153.4 to 0.155.1. The isolated merge surface was 37
  conflicts (110 files changed on both sides); the 0.155.1 retarget itself
  conflicted only on the workspace version in `codex-rs/Cargo.toml`.
- Guardian retained-context and catalog-window fixes: Guardian image
  admission stays the vanilla per-item 10k cap; operator `model_catalog`
  windows survive turn-context re-resolve.
- Compaction summary source is the rewritten-file split (bands + post-boundary
  native tail + grafted MidTurn pairs), not a blanket tail prune.
- Sanitized-transcript recovery is restored through the history-reset drill
  at the new `patches/lhc/BASE`.
- Hosted sandbox gate is standing: dispatch-only workflow, `binary_id()`,
  retries 0. Candidate hosted 60/60 green on this sync.
- F2 resume: rewritten `TurnStarted` / `TurnAborted` / `TurnComplete` ids
  come only from proven bindings (closing `turn_end` keys, or the capture-bound
  live turn). Unproven legacy ids stay synthetic and warn at rewrite. There is
  no migration of existing rollouts.

## Known issue

During late command completion after interruption and LHC compaction, history
projection can log two `dropping turn-scoped item` warnings: the item is
projected twice, with one pass unowned. The user-visible exec item remains
retained under the correct host turn UUID, and resume shows one interruption
banner. This is a known log residual accepted for this release. Evidence:
`evidence/C/candidate-35473451520/F2-WARNINGS.json`.

## Thread schema and migration

LHC thread schema remains 13. This release introduces no schema migration
and no F2 rollout-id migration.

## Packages

The five native archives (Linux x86-64/ARM64, Windows x86-64/ARM64, Apple
Silicon macOS) retain the canonical Codex package layout. Every package
contains Codex, Code Mode host, bundled ripgrep, canonical metadata, and LHC
provenance. Linux packages also contain bwrap and patched zsh; Windows
packages contain the command runner and sandbox setup helpers.
